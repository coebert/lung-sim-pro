
- All conventional breaths are BreathSpecs solved as a closed-form periodic RC steady state (affine start→end volume map, patient effort Pmus superposed) PSV/SIMV breaths come from an event timeline driven by the patient's continuous effort clock (trigger threshold, synchronisation window, residual volume carried breath to breath), and APRV (with patient effort) uses the shared aprvTrajectory module for trace, scoring and release metrics; P-V loops plot raw Paw for pressure modes — why: one physics source keeps pressure, flow, volume, PRVC targeting and loops consistent with carried trapped volume.
- Measured values come from breath-by-breath tracking (measurement.ts BreathTracker) inside LiveSimulation, which both simulationStore and headless tests drive; displayed EtCO₂ is sampled from the capnogram while Vitals.paco2 is the modelled alveolar CO₂ — why: live app, tutorials and tests must measure identically and never report gas exchange without delivered breaths.
- Tutorial steps declare `modes`, `needsVentilation` and a `solution` patch and are evaluated only via `evaluateStep` with a fresh-revision context; tutorialWalkthrough.test.ts replays every solution — why: success messages must reflect delivered ventilation in a compatible mode, and hints must provably work.
- Standalone bedside and ventilator routes share the Bedside page shell and BedsideView, using the same simulation store as the simulator — why: comparison preserves patient/settings and uses identical live physiology rather than separate demo traces.
- BedsideView displays pressure, flow and volume simultaneously from shared live buffers, with buffer-based scale headroom — why: all three traces must stay synchronized with the simulator and remain visible during high-flow breaths.
- Mobile devices see P–V and F–V loops through the Loops sheet in MobileShell's bottom nav (portrait and landscape), not a side column — why: phone traces stay readable while loops remain reachable, drawn from the same buffers and axis fitting as the desktop VentilatorPanel.
- Bedside capnography renders the shared capno buffer in kPa using the monitor's unit conversion and capnography color — why: its trace, numeric reading and freeze state must match the simulator without separate physiology.
- Shared capnography uses mode-specific breath timing and exhaled volume from generateVentWaveformPoint for dead-space washout, mixed-gas upstroke and plateau, with an inspiratory sensor downstroke — why: CO₂ morphology must follow actual simulated breaths rather than a fixed I:E clock; this remains a teaching model, not recorded clinical data.
- Native iOS packaging uses Capacitor with bundled dist assets and no `server` block; `npm run ios:prepare` (scripts/ios-prepare.mjs) runs a source-only preflight, build, sync, then a strict post-sync check requiring native config + bundled index.html and rejecting remote/cleartext config (see docs/IOS_RELEASE.md) — why: App Store builds must run offline from bundled files.
- Full-screen page roots use `app-safe-area` with viewport-fit=cover — why: content stays clear of the iPhone notch and home indicator.
- Control ranges and per-mode availability live in controlSpecs.ts, used by VentilatorControls and by tutorial reachability tests — why: every tutorial answer key must be settable on screen.
- EtCO₂ is shown everywhere via etco2Display (dash when unavailable/measuring; trends store NaN gaps); tutorial steps stay complete only while still met unless marked `transitional` — why: no invalid CO₂ number or stale success is ever shown.
